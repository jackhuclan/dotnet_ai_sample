## 2. 产品概述

### 2.1 背景与目标

需要一个**开箱即用的本地桌面 AI 对话客户端**，用最小依赖跑通「多轮对话 + 技能（系统提示词预设）+ 流式输出 + 本地持久化」的完整链路，作为后续半导体领域智能体能力的承载界面与验证底座。

**产品目标**

| 编号 | 目标 | 达成判据 |
| --- | --- | --- |
| G1 | 桌面上可直接运行的多轮 AI 对话客户端 | 双击 exe 即可对话，无需额外配置步骤 |
| G2 | 支持"技能"这一可复用的提示词资产 | 技能的增删改查、在对话中选择与注入全部可用 |
| G3 | 对话与配置在进程重启后完整恢复 | 重启后会话列表、消息历史、多轮上下文、技能库均保持一致 |
| G4 | 界面达到可对外演示的完成度 | 视觉细节（间距、圆角、配色、文案）逐项对齐设计预期 |
| G5 | 工程结构可长期演进 | 服务层接口化 + DI 容器 + 分层自动化验证 |

### 2.2 产品定位

- **形态**：单机桌面应用（Windows），手机竖屏比例的独立窗口。
- **不做**：不做服务端、不做多用户/账号体系、不做云端同步、不做插件市场。
- **定位**：个人本地 AI 助手 + 领域智能体的界面原型底座。

### 2.3 目标用户与典型场景

| 用户 | 场景 | 期望 |
| --- | --- | --- |
| 产品负责人（主要） | 演示领域智能体能力、验证交互稿 | 界面完成度高，可投屏演示 |
| 开发者 | 扩展新的模型/技能/工具 | 服务层接口清晰，替换实现不影响界面 |
| 普通使用者 | 日常问答、翻译、代码审查 | 打开即用，键盘操作顺手，历史会话可追溯 |

### 2.4 范围界定

**本期范围（In Scope）**

- 单窗口对话客户端：会话管理、消息收发、流式回复、停止生成
- 技能（系统提示词预设）的完整生命周期
- 模型与接口配置（API Key / 端点 / 模型选择）
- 本地 JSON 持久化
- 结构化日志 + 全局异常兜底
- 分层自动化验证（服务层冒烟 + 离屏 UI 探针）

**非目标（Out of Scope）**

- 流式回复的 Markdown 增量重排优化之外的渲染能力扩展
- 多模态（图片/语音）输入、文件上传、联网检索
- 会话搜索、标签、导出、多端同步
- 安装包制作与自动更新
- 国际化（仅简体中文）

### 2.5 术语表

| 术语 | 说明 |
| --- | --- |
| 会话（Conversation） | 一次独立的对话上下文，含标题、模型、消息历史、MAF 会话序列化数据 |
| 技能（Skill） | 一段可复用的系统提示词（System Prompt）预设，在对话中作为 `Instructions` 注入模型 |
| 抽屉（Drawer） | 覆盖在聊天区之上的浮层侧栏，用于承载会话列表 |
| Chip | 输入区上方显示"当前已挂载技能"的小标签，可一键取消 |
| MAF | Microsoft Agent Framework（`Microsoft.Agents.AI`），负责 Agent 抽象与会话管理 |
| 离屏探针（UiProbe） | 不依赖鼠标/键盘模拟的 UI 自动化验证程序，直接实例化窗口并驱动命令，可渲染截图 |
| 冒烟测试（SmokeTest） | 服务层真实调用大模型 API 的端到端验证 |

## 5. 功能需求

优先级：**P0** = 核心链路，缺失即不可用；**P1** = 体验必需；**P2** = 增强项。
状态：本版本全部为 **已实现 / 已验收**。

### FR-1 应用启动与宿主（P0）

| 编号 | 需求描述 | 验收标准 |
| --- | --- | --- |
| FR-1.1 | 应用以 .NET 通用主机（`Microsoft.Extensions.Hosting`）启动，用 `HostApplicationBuilder` 配置服务与日志 | 启动流程为：建主机 → 接线日志 → 注册服务 → 启动主机 → 加载持久化数据 → 容器解析主窗口 |
| FR-1.2 | 主窗口与全部 ViewModel 由容器解析，依赖自动注入 | 主窗口 `DataContext` 为 `MainViewModel`，其依赖全部来自容器 |
| FR-1.3 | 启动期持久化数据加载顺序固定为 配置 → 技能 → 会话 | 会话的模型名回落使用已加载的配置，日志中可观察到该顺序 |
| FR-1.4 | 退出时优雅关闭：停止主机 → 释放容器 → 刷新日志 | 正常关闭后日志中可见「MegaAgent 正在退出（ExitCode=0）」 |
| FR-1.5 | 全局异常兜底 | UI 线程异常、后台线程异常、未观察的 Task 异常三类均写入日志；UI 线程异常额外弹出可读提示且不中断当前会话 |

### FR-2 主窗口与布局（P0）

| 编号 | 需求描述 | 验收标准 |
| --- | --- | --- |
| FR-2.1 | 窗口固定尺寸 450×800 DIP（≈9:16 手机比例），禁止缩放 | 窗口无最大化按钮、拖拽边框不改变尺寸 |
| FR-2.2 | 窗口启动居中显示 | 首次启动位于屏幕中央 |
| FR-2.3 | 顶栏自左至右：会话抽屉开关（☰）、当前会话标题、生成中指示、用户头像 | 生成中时显示 LoadingCircle + 「生成中…」文案 |
| FR-2.4 | 聊天区始终占满窗口宽度，会话抽屉以浮层形式覆盖其上 | 抽屉展开/收起过程中，聊天区布局不重排、不抖动 |
| FR-2.5 | 无会话时显示引导占位「点击左上角「☰」打开会话列表开始」；有会话但无消息时显示「还没有消息，输入内容开始对话吧」 | 两种空状态按条件互斥出现，任何时刻最多只有一条可见（B13 前两者会叠加显示）。冷启动因 FR-4.10 自动建会话，正常情况下直接呈现「还没有消息」状态 |

### FR-3 会话抽屉（P0）

| 编号 | 需求描述 | 验收标准 |
| --- | --- | --- |
| FR-3.1 | 抽屉默认隐藏，启动时不占位 | 应用启动后看不到会话列表 |
| FR-3.2 | 通过顶栏 ☰ 展开；展开宽度为聊天区宽度的 50% | 抽屉宽度取自窗口首次布局后聊天区实际宽度的 50%，展开后恰好覆盖聊天区一半 |
| FR-3.3 | 抽屉以滑入动画展开（220ms，CubicEase InOut），并显示半透明遮罩 | 动画结束后抽屉完全贴合左边缘，遮罩覆盖剩余区域 |
| FR-3.4 | 点击遮罩空白处关闭抽屉 | 点击遮罩任意位置抽屉收起，聊天区恢复可交互 |
| FR-3.5 | 抽屉内顶部为「新建对话」与「« 收起」同行，其下为「历史对话」标题与列表 | 抽屉内不出现品牌区/Logo 等冗余内容 |
| FR-3.6 | 抽屉关闭时同步关闭会话「…」菜单，避免浮层残留 | 收起抽屉后无孤立菜单 |

### FR-4 会话管理（P0）

| 编号 | 需求描述 | 验收标准 |
| --- | --- | --- |
| FR-4.1 | 新建对话：创建空会话并置顶，若未配置 API Key 则先提示并引导至模型设置 | 未配置 Key 时点击「新建对话」弹出提示且自动打开模型设置 |
| FR-4.2 | 会话列表项展示标题与日期副标题（次级文字，11px）：今天/昨天显示「今天 HH:mm / 昨天 HH:mm」，同年显示「M月d日」，跨年显示「yyyy年M月d日」；悬浮提示完整时间「yyyy-MM-dd HH:mm」 | 标题过长时以省略号截断，不撑破列表；列表项任何位置不再显示模型名（模型在输入区下拉切换） |
| FR-4.3 | 每条会话项右侧提供「…」更多操作入口 | 点击「…」不切换当前会话（拦截冒泡），仅弹出菜单 |
| FR-4.4 | 菜单含「重命名」「删除对话」两项 | 两项均带左侧图标 |
| FR-4.5 | 删除必须先二次确认，取消则不作任何改动 | 确认弹窗标题「删除会话」，确认按钮文案「删除」，取消按钮文案「取消」 |
| FR-4.6 | 重命名以**行内文本框**呈现，默认全选原标题 | 进入重命名时原「…」按钮与常规展示区均隐藏，文本框获得焦点且内容全选 |
| FR-4.7 | 重命名确认方式：Enter 确认、Esc 放弃、点击别处视为确认 | Enter 后标题生效并落盘；Esc 或空白输入保持原标题 |
| FR-4.8 | 右键会话项提供同样的「重命名 / 删除对话」入口 | 右键菜单功能与「…」菜单一致 |
| FR-4.9 | 删除当前会话后自动切换到列表中的下一条 | 当前会话被删除后消息区无残留内容 |
| FR-4.10 | **冷启动（conversations.json 不存在或为空）时自动创建一个「新对话」**：置顶、设为当前会话、模型取「模型设置」里的默认模型 | 启动后消息区直接呈现空会话状态（「还没有消息」），无需手动新建；自动会话随首次实际使用一并落盘 |

### FR-5 消息与流式回复（P0）

| 编号 | 需求描述 | 验收标准 |
| --- | --- | --- |
| FR-5.1 | 用户输入以**蓝底白字**气泡靠右显示 | 气泡背景固定为 `#346EF3`、文字 `#FFFFFF`，不随主题变化 |
| FR-5.2 | 助手回复气泡靠左显示，按 Markdown 渲染 | 使用 MdXaml + GithubLike 样式；消息内不出现滚动条 |
| FR-5.3 | 回复以流式方式逐字呈现 | 首个 token 到达即显示，非等待完整回复 |

### 6.3 样式体系

基于 HandyControl，`SkinDefault` + `Theme` 资源字典在 `App.xaml` 合并；在主题之上仅追加承载布局语义的自定义样式：

| 样式键 | 用途 |
| --- | --- |
| `MdViewer` | Markdown 渲染视图（透明底、无边框、无工具栏、GithubLike） |
| `FormLabel` | 表单标签（半粗、12.5、上间距 14） |
| `FieldError` | 必填错误提示（危险色、11.5） |
| `HintText` | 次级提示文字 |
| `GhostIconButton` | 透明底图标按钮（自建，替代不渲染普通内容的 `ButtonIcon`） |
| `MenuItemButton` | 浮层菜单项（整行可点、左对齐、圆角高亮、高度放开） |

**实现约束（历史坑，需求层面的硬性要求）**

- HandyControl 的按钮模板带固定高度，多行/超高内容会被裁切 → 承载多行内容的按钮必须放开高度约束（`Height=Auto`、`MinHeight=0`）；头像等圆形元素直接使用 `Border` 承载。
- 列表项内容默认不横向拉伸，会导致右侧操作按钮不贴右缘 → 需显式设置横向拉伸与内边距。
- 助手消息的 Markdown 渲染控件本身是 `ScrollViewer`，会吞掉鼠标滚轮 → 必须在隧道（Preview）阶段由外层消息区接管滚动。

## 8. 验收与测试方案

### 8.1 分层验证策略

采用三层验证，优先级由高到低：

1. **UiProbe 离屏 UI 探针**（主力手段）——不依赖鼠标/键盘模拟，直接实例化窗口与 ViewModel、驱动命令、断言视觉状态、渲染 PNG 截图。每个用例自建独立 DI 容器，并备份/还原应用数据目录下的 JSON 数据，用例间完全隔离。
2. **SmokeTest 服务层冒烟测试**——真实调用 DeepSeek 接口，验证"发送 → Agent → 流式回复"链路。
3. **真实应用运行验证**——经宿主启动真实程序，人工/截图确认。

> 说明：合成鼠标点击（PostMessage 投递 `WM_LBUTTONDOWN/UP`）在本机后期整体失效，UI 验证一律改走离屏探针。
