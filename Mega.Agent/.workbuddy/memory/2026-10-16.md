## 第十一轮改造（保存按钮禁用 + 三对话框 MVVM 化 + 消息区滚轮修复）
- **必填为空 → 保存按钮禁用**：ViewModel 暴露 `CanSubmit`（= 所有必填非空 && !IsTesting），`[RelayCommand(CanExecute = nameof(CanSubmit))]` + 在 ApiKey/Endpoint/IsTesting 等 ObservableProperty 上 `[NotifyCanExecuteChangedFor(...)]`。CommunityToolkit 的 RelayCommand **不会**自动订阅 INotifyPropertyChanged 重查 CanExecute，必须显式加 NotifyCanExecuteChangedFor。
- **hc:PasswordBox.Password 终极结论：是普通 CLR 属性（反射确认 PasswordProperty 字段不存在），`Password="{Binding ...}"` 直接抛 XamlParseException**。解法：自建附加属性 `Views/PasswordBinding.cs`（`local:PasswordBinding.Password="{Binding ApiKey, Mode=TwoWay}"`）——FrameworkPropertyMetadata 默认值用 **null**（保证绑定首推 "" 时回调必触发、从而挂上内部控件事件）；OnPasswordChanged 里同时设置 box.Password 与 PART_PasswordBox.Password（部分模板不回推）；内部控件 PasswordChanged → PushToSource（IsSyncing 标记防死循环）。双向绑定实测通过（VM→控件、控件→VM）。
- **必填红框改 MVVM 声明式**：新建附加属性 `Views/RequiredBorder.cs`（`local:RequiredBorder.HasError="{Binding XxxHasError}"`）——为 true 时 SetCurrentValue(BorderBrush/BorderThickness)，false 时 ClearValue 恢复样式。删除了旧 RequiredField.cs。探针判定红框要 `ReferenceEquals(control.BorderBrush, Application.Current.TryFindResource("DangerBrush"))`，不能靠 RGB 阈值猜。
- **三个对话框 MVVM 化**：新增 ViewModels/SettingsDialogViewModel、SkillEditorDialogViewModel、SkillsDialogViewModel + IDialogService（View 实现并注入，SkillsDialog 自身实现：ShowSkillEditor/Confirm）。XAML 全绑定驱动（Text/Password/SelectedItem/Command/Visibility），代码后置只留构造 VM + CloseRequested→DialogResult/Close（非模态探针下 DialogResult 赋值抛异常需 try-catch）。SkillsDialog 双击编辑用 `<ListBox.InputBindings><MouseBinding MouseAction="LeftDoubleClick" Command="{Binding EditCommand}"/>`（零代码后置）。Skill 是普通 POCO，编辑后用 `Skills[index] = selected` 强制列表刷新。
- **命令按钮的探针验证法**：`RaiseEvent(ClickEvent)` 只触发 Click 处理器、**不会执行命令**（命令在 ButtonBase.OnClick 里 ClickEvent 之后执行）——必须用 `new ButtonAutomationPeer(btn).GetPattern(Invoke).Invoke()` 走真实 OnClick 路径。
- **模态子窗口探针等待**：`Dispatcher.BeginInvoke` 排队会被「队列动作先于子窗口注册」的时序问题吞掉（实测打印"未找到子窗口"后 ShowDialog 永久阻塞）→ 改用 **DispatcherTimer(50ms) 反复探测 Application.Current.Windows**，超时强制 Close 防卡死。
- **消息区滚轮失效根因**：助手消息的 `md:MarkdownScrollViewer` 本身是 ScrollViewer，OnMouseWheel 会把滚轮事件标记 Handled，外层 ChatScrollViewer 收不到 → 鼠标停在消息上时列表不滚。`ScrollViewer.HandlesMouseWheelScrolling` 是普通 CLR 属性（**不是**依赖属性，Style Setter 写会 MC4005），只能代码设置；最简可靠解法：外层 ScrollViewer 挂 `PreviewMouseWheel`（隧道阶段先于内层收到）→ `ScrollToVerticalOffset(VerticalOffset - e.Delta * 0.5)` + Handled=true。探针用 `new MouseWheelEventArgs(Mouse.PrimaryDevice,0,-120){RoutedEvent=UIElement.PreviewMouseWheelEvent}` 在 MarkdownScrollViewer 上 RaiseEvent 验证（0→60→120，CHAT-SCROLL PASS）。
- 转换器 BoolToVis/NullToVis/CountToVis 从 MainWindow 资源提升到 App.xaml 全局（对话框共用），MainWindow 里的本地声明保留（同名本地优先，无冲突）。
- 全部回归 PASS：SETTINGS-MVV / SKILL-EDITOR-MVV / SKILLS-DIALOG-MVV / CHAT-SCROLL / ENTER-SEND / CONVERSATION-MENU。探针会写 config.json 与 skills.json → 同样用 %TEMP% 备份 + finally 还原。
